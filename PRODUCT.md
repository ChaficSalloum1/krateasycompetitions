# Krateasy Competitions — product authority

Status: ACTIVE on the compiler-runtime-reset branch. Source: [authority record](docs/AUTHORITY_SOURCES.md).

## Destination

Krateasy is the general competition compiler and runtime, with independent Tournament Guard. An organiser provides unfamiliar competition intent, inspects and corrects an explicit model, resolves ambiguity, locks the definition, compiles qualification and draw, generates a valid schedule, receives independent evidence, approves changes, publishes, runs, repairs and completes the event without engineering intervention within supported semantics.

Play & Konnect is the branded organiser, participant and public application consuming that same core through stable domain contracts. It remains live on its existing system until parity, shadow and incremental cutover gates pass. Its database is not the integration contract.

## Ownership and preservation

`krateasycompetitions` owns Definition, compiler, standings, qualification, seeding, topology, placement, scheduling, independent assurance/Guard, revisions, runtime, recovery, scenarios and generic organiser Studio. Preserve the existing schema, engine, CP-SAT integration, revision hashes, publication safety, replay, live operations and tests. Audit and connect existing code; do not replace it for a tidier folder layout.

`play-konnect-tournament-os` owns the P&K experience, score capture, player proposals/conflicts, public views, event-day interactions, WSO / Set Winners and P&K configuration. Preserve this behaviour. Retire hardcoded playbook runtime truth, singleton configuration and startup repair gradually through H–J, never by starting a second generic engine.

## Product loop and confidence

Interpretation proposes; the organiser or governed deterministic translation approves explicit semantics. The compiler proposes artefacts; Run Assurance independently checks them. Guard protects consequential commands using fresh exact server-owned artefacts. UI and public projections are never authoritative.

Supported input adapters first: natural language, JSON/YAML, CSV/XLSX in C. PDF/ZIP/images are deferred adapters. Ambiguous comparison or unsupported rules remain visible decisions or unsupported findings. “Any tournament” is a product direction, not a present capability claim or permission to guess.

A passing unit suite is bounded evidence, not production readiness. A fixture does not establish historical parity merely because it is labelled P&K. Existing code or historical delivery reports do not close the new programme gates without mapped acceptance evidence.

## Finite scope

Follow A–N exactly as defined in [BUILD_PLAN.md](BUILD_PLAN.md). A–G build the compiler product; H–J migrate P&K; K–L complete generic runtime/recovery; M provides external Guard; N proves structural generality. There is no architectural Phase O.

Not authorised now: new platform authentication/organisation surfaces, social graph, Ticket Tailor replacement, Wallet, sponsor tools, broad league UX, large analytics, premature multi-sport abstractions, P&K cutover, or a second engine in either a browser prototype or P&K.
